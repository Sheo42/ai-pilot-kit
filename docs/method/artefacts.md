# Artefacts

Each artefact exists because a session without memory would otherwise lose
or contradict something. Each has one owner and one rule that keeps it
alive.

| Artefact | Where | Owner | Kept alive by |
|---|---|---|---|
| Project definition | `docs/project-definition.md` | Owner, business analyst | Re-read before each ADR; defaults re-checked before they become decisions |
| Requirements | `docs/requirements/<module>.md` | Business analyst | Template, stable IDs, merge approves; CI checks IDs are unique |
| ADRs | `docs/adr/` | Architect | Index, never renumbered, superseded not rewritten; CI checks numbers |
| Architecture views | `docs/architecture/` | Architect | Every ADR updates the view it changes, in the same PR |
| Interface specs | `docs/interfaces/` | Architect | Versioned from day one; checked by code (schemas) |
| Traceability | generated by `scripts/ci/trace.py` | Tester | Test tags; CI fails on a tag naming no AC and on an uncovered AC of a passed gate |
| Link diagrams | generated by `scripts/ci/links.py` | PR reviewer (pastes them) | Mermaid, in the run summary and the merge summary; CI fails on a `Related` link to nothing |
| To-do list | `docs/todo/`, one file per number range | Every role | Every task updates it; CI checks IDs, ranges and order and prints the view |
| Glossary | `docs/glossary.md` | Every role | New term added in the same change; CI checks duplicates |
| Reviews | `docs/reviews/` | Challenger, author | One file per challenge plus the author's answers; the owner's calls recorded |
| Mutation ledgers | `docs/mutation/`, one file per run | Tester | A verdict per survivor; a fresh session checks a sample; the gate needs none left without a verdict |
| Threat models | `docs/security/` | Security engineer | Updated when an interface or command appears |
| Chronicle | `docs/chronicle/` | Chronicler | One entry per session; agents history; lessons |
| CI checks | `scripts/ci/`, `.github/workflows/` | Developer | Thin workflow calling scripts that run on any computer |
| Project memory | outside the repository | Every thread | One file per subject; points to the repository |

## Conventions shared by all artefacts

1. **IDs are forever.** `REQ-<MOD>-<NNN>`, `REQ-...AC<n>`, `ADR-NNNN`,
   `TODO-NNN`: never reused, never renumbered. A duplicate is closed as
   "Dropped: merged into ...", not deleted.
2. **Codes in IDs, plain words in file names.** Coded file names are
   unreadable; the first project renamed them on day two.
3. **Links instead of copies.** The chronicle links to ADRs instead of
   repeating them; vendor documents are summarised and cited, never copied.
4. **Status changes by merge.** A PR sets its requirements to Approved and
   its ADRs to Accepted before asking for the merge; the merge makes it
   true.
5. **The to-do list is the single open list.** "Waiting on" the owner holds
   decisions and questions only the owner can answer; "Team work" holds the
   rest, with priority (P1 blocks the next step, P2 current phase, P3
   later), owner and "Blocked by".
